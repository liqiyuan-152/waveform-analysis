## Goals / Non-Goals

**Goals:**

- 按变化依赖优化已有实现，以兼容回归和真实测量决定效果。
- 补齐无响应恢复、可访问性及工程检查的可验证契约。
- 将每个阶段保持为可独立验证、撤销的改动。

**Non-Goals:**

- 不迁移 Canvas/WebGL，不扩大公共 API，不改变 immutable data、秒坐标及受控状态规则。
- 不默认引入 transferable、几何缓存或新的依赖，不预先承诺提速比例。
- 不在本变更清理历史证据、重写 Git 历史、迁移 LFS 或重建 CodeGraph 索引。

## Decisions

### 1. 先补门禁和测量，再调整运行时

基线记录包括 commit、已有改动、Node/pnpm、浏览器版本、硬件、命令和退出码。浏览器测量覆盖单/多通道、10 万/100 万点、对象与紧凑输入；重点比较只改颜色、只更新一个通道、嵌套配置更新以及点/误差棒动画。同环境预热后至少五次，记录中位数、p95、分配与可用内存指标，并明确不能观测的指标。若成本过高，分批执行矩阵并逐项记录，不以 jsdom 耗时代替浏览器性能。

优先复用现有测量脚本，只补缺少的场景；不创建第二套基准平台。候选优化必须有前后数据，重复测量仍无法解释的退化应修复或撤销；没有可靠收益的候选以“不采用及理由”完成决策任务。

### 2. 使用显式依赖映射细分更新

在现有调度阶段上区分布局、几何、样式和交互配置的影响，混合 patch 使用所需工作的并集。不能只扩大 samplingIndependentOptions 就认定优化完成，因为当前 changed 仍清空布局快照并让后续阶段执行。

首批纯样式白名单限定为 `lineColor`：只有实际变化字段均为该字段且没有数据、布局或交互能力变化时，才复用布局与采样结果。空 patch 或全为相同值不产生有效更新；白名单之外的字段和混合 patch 仍执行原有必要的更新及取消策略。字号、标题尺寸、轴格式、可见性、网格及域变化不进入纯样式分支。后续扩展白名单必须补充字段影响分析、场景和回归。

目前通用 setOption 会取消手势及标注编辑；本次明确将仅颜色更新改为保留活动交互，不再要求保留这项取消行为。其他公共事件载荷和受控提交规则不变。各状态采用以下确定规则：

| 状态                 | 仅颜色更新后的预期                                           | 验收要点                                                                 |
| -------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 框选或平移拖拽       | 保留 pointer capture、起点、当前选择和视口，继续接受 move/up | 与无颜色更新的同一指针序列得到相同域及手势事件；更新本身不发手势事件     |
| 待提交滚轮缩放       | 保留 pending domain、帧提交及结束防抖期限，不清空或重启      | 同一滚轮输入产生相同 zoom-change/zoom-end 次数、载荷和最终域             |
| 标注编辑、草稿或拖拽 | 保留未保存内容、焦点、选区、拖拽偏移和指针状态               | 颜色更新不触发 annotation-create/update/delete；原提交、取消操作继续有效 |
| 活动动画             | 保留原任务、起始时间、进度和终态目标，用最新颜色绘制后续帧   | 不重启动画，不强制 finish/cancel，不新增完成回调；最终几何保持一致       |

有效颜色更新仍产生新的业务 revision、使正在进行的导出按既有 export-stale 规则失效，并按正常渲染调度报告 rendered；finished 仅在最新 revision 的采样、动画和渲染稳定后报告。更新不能制造手势、标注或动画完成事件。原生和 Vue 入口采用相同行为；README 和兼容记录必须写明这一改进。相比自动推断对象差异，显式映射更易审计新增字段遗漏。

### 3. 数据和资源按稳定身份复用

以系列稳定 ID、SingleWaveformData 引用及影响准备结果的元数据为复用条件，保留必要的原始输入索引。仅按 ID 缓存不安全：同 ID 的新数据必须刷新源、域、误差范围和查询。元数据变化按影响重新准备或重组描述；重复 ID、排序、空序列保留既有归一化规则。

Worker 数据集与采样签名同步按系列版本失效，更新一条曲线不重置其他有效数据集；删除、改 ID 和 dispose 释放对应资源。缓存必须受当前数据或明确预算约束。拒绝全局永久 Map 和输入内容深比较，避免长期保留旧数据或每次遍历全量点。

按序列失效必须同时处理在途请求。每条注册或采样请求记录所涉及的数据集版本与 generation；替换或删除任何参与数据集时，将旧请求的 Promise 以内部取消结果结束，清理 deadline 和 pending 项，并使调度器退出旧 run。不能仅清除计时器、删除 Map 项或递增 token。包含多个系列的旧采样批次整体取消，按当前视口重排最新批次；未变化且已确认注册的数据集保留，不因批次取消重复注册。注册确认必须匹配当前数据版本；迟到确认及输出不得写回 revisions、缓存或诊断。正常失效不报告 sampling-error，取消 rejection 必须被所有注册/采样等待链捕获。

在 Worker 可继续响应时，最新请求必须能在旧 deadline 到期前启动并完成；若传输本身失联，最新请求受自己的有限 deadline 约束，进入超时恢复。dispose 后只结束等待和回收资源，不再启动新任务。

### 4. Worker 请求必须有限结束

增加可注入的内部时钟和有限 deadline，生产初值采用 30 秒，基于最大规模冷启动测量复核；不新增公共配置项。超时触发既有故障处理路径，清除请求与计时器、终止失联 Worker，并通过 generation/token 忽略迟到结果。reset、dispose、正常响应和同步发送异常均回收 timeout。

统一请求终结入口保证成功、失败、取消或超时中仅一个结果生效，并先结束等待再释放其记录。终止失联 Worker 时，所有依赖该传输的未完成请求均须结束或转入受控恢复，不留下等待旧传输的 Promise。数据替换的取消规则见决策 3；替换或取消本身不得重启旧请求的 deadline。

保持 raw 不建 Worker；auto 及允许 JavaScript 回退的模式可恢复；强制 wasm/error 仍报告既有 sampling-error，保留有效路径或占位，不静默改成 JavaScript 成功。使用假时钟验证无响应，不引入真实等待 30 秒的测试。

现有 WorkerSamplingClient.fallbackRepository 通过循环 replace-dataset 重放 revision；在长期保留数据集后，这会使一次恢复反复归一化同一最新数组。本次必须改为从每个当前有效数据集的最新快照和版本直接建立回退状态，或建立一次后使用显式版本映射；不重放中间 revision，不保留历史数据快照。内部恢复接口不扩大公共导出。每个有效数据集在一次恢复中至多准备一次，成本随当前数据总量变化，不随历史更新次数累积；过期、删除及取消版本不得被恢复。

增加 revision=1 与 revision=1000、相同当前数据规模的对照：以准备/注册计数验证每个数据集只处理一次，测量恢复耗时和内存；回退结果、后续更新版本匹配及再次故障行为均需正确。计数断言是确定性门禁，耗时不使用容易波动的固定毫秒阈值。

传输优化先画出消费者输入、私有源、主线程回退副本、Worker 和 WASM 的所有权图。直接 transfer 私有副本会 detach 客户端缓存所持数据，必须先解决回退副本重建或保留策略；以总复制量和峰值内存决定是否采用，不能只比较 postMessage 时间。消费者缓冲区始终不得 detach。

### 5. Vue 快照单次生成，差异语义保持

组件负责追踪嵌套响应式配置并生成快照，适配器使用明确的内部快照入口接收；保留直接适配器调用所需的防御性快照边界。data 保持不透明引用，不观察点数组内部。对 annotations、formatter、undefined、循环引用及嵌套字段修改进行回归。相比仅用浅比较，此方案保留已有嵌套配置更新能力。

装饰几何缓存独立决策：若采用，键须反映点集合、比例尺 domain/range、点类型、误差棒设置和动画帧；不能只按可变 D3 scale 对象身份缓存。限定当前几何或容量，销毁后可回收。

### 6. 独立命令完整，组合构建避免重复

保持 typecheck、build、dev、test、test:coverage、test:package 及直接 pack 的现有准备语义。将内部阶段组合去重；如跨命令缓存，摘要必须覆盖源文件、配置、工具链和产物完整性，产物缺失或被改写时重建，不能仅以目录存在跳过。

普通 CI 和两条发布验证入口显式接入三项已有检查，失败返回非零；不削弱 frozen install、WASM 验证、覆盖率、ESM/CJS/声明/CSS 和独立包消费。将纯计算测试与依赖 DOM 的测试分为明确测试项目，保持发现范围和覆盖率统计完整，不能因环境拆分漏跑测试。

本项不替换 terser 或引入产物分析工具，相关决策继续归 `project-optimization-2024` 阶段 5 所有。

### 7. 语义与文档更新

图例列表项由外层结构承载，交互元素保留原生 button 及 aria-pressed；保持点击、Enter/Space、焦点和隐藏状态行为。非交互图例不得误报可操作按钮。除自动断言外，记录一次真实辅助技术的名称、版本和验证结果；无法执行时明确未验证。

AGENTS.md 对齐 chart/model/data/layout/view/adapters 和 demo-app 的当前职责，说明 CodeGraph 索引过期时读取当前源码、索引更新由用户决定。本变更文档使用相对证据路径，临时运行产物和可提交的摘要按 `project-optimization-2024` 任务 3.1–3.3 衔接，保留既有链接和文件。

## Risks / Trade-offs

- 失效映射遗漏字段 → 使用混合 patch、动画、导出和受控状态回归，新增字段必须明确分类。
- 复用过期源或 Worker 输出 → 数据引用与系列版本双重验证，覆盖删除、重排、同 ID 替换与乱序响应。
- 清理失效请求却未结束等待 → 使用统一终结入口，验证新任务在旧 deadline 前启动并完成，包含多系列批次和在途注册。
- 高 revision 故障恢复重放历史 → 仅按当前快照重建一次，使用 revision=1/1000 的准备计数和结果对照。
- transfer 破坏回退 → 所有权测试先行，收益不成立则保留克隆策略并记录决策。
- 超时误判冷启动 → 先测最大规模冷启动，必要时调整内部有限阈值，保留假时钟测试。
- 测试拆分虚增覆盖率或漏跑 → 比对测试清单与计数，检查未导入文件及构建产物是否计入，保留既有门槛。
- 构建缓存误复用 → 验证冷启动、源/配置/工具版本变化及产物破坏，不允许无条件 skip。
