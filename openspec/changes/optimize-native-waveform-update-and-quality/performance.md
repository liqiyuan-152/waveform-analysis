# 更新性能与候选决策

## 方法与边界

Apple M1 / macOS arm64、Node 22.23.2、pnpm 10.32.1、Chromium 141.0.7390.37，生产 bundle，1200×720 图表，关闭动画，auto 采样最多 1200 点。每种输入预热五次，再记录五次；p95 是五个样本中的最大值，只用于本机比较。数据生成不计入更新耗时。同步时间为 setOption 返回；稳定时间包含采样、帧调度和 SVG 导出屏障，不等同于纯计算或屏幕首次呈现时间。原始样本、主线程同步耗时、布局数、注册数和 CDP 堆采样均保留。

可复核结果：基线五次预热（历史验证文件，已清理）、最终五次预热（历史验证文件，已清理）。基线使用冻结的原实现生产 bundle，其源码摘要沿用 baseline-corrected.json；instrumentationSourceSha256 表示采集脚本版本，不能将其当作基线库实现摘要。最终报告的 sourceSha256 覆盖源码、脚本和浏览器 fixture。

早期 baseline.json 的完整替换复用了首通道子数据引用，后续已用每通道新描述对象修正；保留原数据，比较只使用修正后的完整替换。此前一轮各五次样本及十次复测见 optimized-final.json、variance-check.json，用于识别帧节拍和异步波动，不挑选最快样本。

完整替换保留原来的全量 reset 路径：只有不存在任何相同 ID/源时才重置全部资源；部分替换走按源失效。这样保留整体替换原有的取消和准备时机，避免逐条 dispose 及无意义的第二次 hysteresis 采样。独立受控测试断言一次 dispose-all、最新值、无遗留计时器和无需额外等待。各规模完整替换的结果及波动均在表中公开，不将整体替换计入局部更新的收益。

CDP Runtime.getHeapUsage 记录的是更新后 JS 堆与 backing storage，不是分配次数、峰值或进程总内存；GC 时机不同会造成下降/负差值。Worker 堆、WASM 线性内存、SVG/GPU 和跨线程峰值未直接观测，因此不能据此宣称总内存或分配降低。误差域、最近点及标注仍使用完整源，未以减小输入换取速度。

## Vue 与恢复

Vue 场景使用 100 个标注并修改嵌套图例背景；确定性快照计数由两次降为一次，直接调用适配器仍防御性复制，data 保持不透明。

Vue 同步 ms（中位数 / p95）：0.7 / 0.8 → 0.7 / 0.8；稳定 ms：49.8 / 51.2 → 45.3 / 47.9。小规模耗时接近噪声，不声称大幅提速。

恢复测试保持当前 100,000 点相同，仅比较 revision=1 与 1000。通过可控 Worker 确认历史版本，故障时使用真实本地仓库；这是恢复阶段测量，不包括历史传输成本。

| revision | 恢复 ms 中位数 / p95 | 每数据集准备次数 | 后续版本 |
| -------- | -------------------- | ---------------- | -------- |
| 1        | 1.7 / 1.7            | 1                | 2        |
| 1000     | 1.6 / 3.2            | 1                | 1001     |

恢复只保存当前快照，不重放历史 revision；连续更新和重复故障通知有确定性准备计数测试。原始报告保留 beforeHeap/afterHeap，仅表示 JS 堆采样。最大场景冷启动稳定耗时为 4733.7 ms，内部 30 秒请求 deadline 有本机余量；该数值不能推断其他硬件或浏览器上不会超时。超时后终止失联 Worker，统一结束等待，并保持 raw/auto/wasm 回退策略。

## 传输候选：不采用

```mermaid
flowchart LR
  A[消费者缓冲区] -->|私有归一化副本| B[主线程源]
  B -->|toWorkerDataset 私有副本| C[当前恢复快照]
  C -->|现状 structured clone| D[Worker 输入]
  D -->|仓库规范化副本| E[Worker 数据集]
  E -->|需要 WASM 时复制| F[WASM 线性内存]
  C -->|候选新增 owned copy| G[可转移输出]
  G -->|transfer 仅 detach G| D
```

按无误差 typed 输入计，现状包含消费者→私有源、源→传输/恢复快照、跨线程 clone、Worker 仓库规范化等复制；WASM 执行另有线性内存复制。安全候选保留恢复快照、额外复制 outgoing 后 transfer，只替换跨线程 clone，并未消除所有复制。点对象和误差数组路径另有整理成本，不将上述计数当成全部输入的统一字节数。

使用真实 Worker 回传 checksum，计时包括恢复快照复制、候选 outgoing 复制、postMessage 及回执；消费者和恢复快照 byteLength 始终完整，候选 outgoing 被 detach，数据校验一致。

| 点数      | clone ms 中位数 / p95 | 安全 transfer ms 中位数 / p95 |
| --------- | --------------------- | ----------------------------- |
| 100,000   | 0.3 / 0.5             | 0.2 / 0.3                     |
| 1,000,000 | 4.0 / 7.6             | 2.0 / 3.9                     |

这是单段 typed 缓冲区的传输探针，未观测整个 Worker/WASM 进程峰值，也未证明完整采样路径收益。收益小于对象点归一化和注册成本，新增所有权及故障复杂度缺少整体证据，因此不接入生产。条件任务 6.5 按不采用分支关闭，不声称已验证生产 transfer 的重试/销毁。

## 几何候选：不采用

每次编码 1200 点及误差棒，100 次，比较无缓存与只记住最后结果的候选。

| 输入         | 无缓存 ms 中位数 / p95 | 候选 ms 中位数 / p95 | 候选实际编码次数 |
| ------------ | ---------------------- | -------------------- | ---------------- |
| 相同静态输入 | 64.5 / 69.7            | 0.6 / 0.7            | 1                |
| 每帧新点集合 | 69.8 / 75.8            | 69.5 / 73.6          | 100              |

静态输入有显著微基准收益，但新帧输入几乎不能命中。生产动画还会原地写入私有投影数组，D3 scale 也可原地变化，按引用缓存会错误复用旧几何；需额外版本或全量指纹才能安全覆盖缩放/resize/动画。当前证据未证明这部分成本后的整体收益，因此不添加生产缓存，条件任务 7.5 按不采用分支关闭。未声称静态缓存没有收益，也未把微基准当成生产动画占比。

## 浏览器与辅助技术

browser-verification.json 与同目录截图覆盖原生/Vue 的 1280×800 和 360×800：图例鼠标/Tab/Shift+Tab/Enter/Space、受控可见性、焦点、滚轮、颜色更新中平移、框选、标注草稿/选区、动画、SVG/PNG、实际 Worker 故障恢复及分页。另记录 workspace/animation/wasm-sampling Demo 路由。Chromium 可访问性树中保留 listitem 内原生 button，非交互状态禁用并移除 aria-pressed。

真实屏幕阅读器未执行，无名称/版本/通过结论；Firefox、Safari、Edge 和移动浏览器未验证。360px 是桌面 Chromium 小视口，不代表移动触摸验证。

## 独立完整替换与首次 SVG 几何更新

对照支持“大对象输入的顺序历史影响了分配/回收成本”：顺序矩阵中 8×100 万点完整替换的约 12% 差值，在挂载后直接替换并显式 GC 时不再出现，同步和首次 SVG 耗时也未增加。这不能证明每一毫秒都属于 GC。局部复用减少了前一步的全量分配，整个操作序列的回收成本发生移动，因此保留两组前置条件的结果。

8×10 万对象点的独立完整替换稳定耗时仍由 339.1→349.5 ms（约 +3.1%、10.4 ms），同步 96.0→95.0 ms、首次 SVG 106.7→104.8 ms。顺序矩阵的 8×10 万 typed 完整替换为 68.0→81.6 ms，同步则 10.2→9.6 ms。颜色 8×100 万 typed 的稳定时间为 42.6→49.0 ms，但同步仅 0.2 ms、零布局/注册；早期同实现的对应稳定中位数还出现过 35.3 ms。稳定屏障包含异步 Worker、帧调度和导出，变化可达到一个帧间隔，不能按同步代码耗时外推。

接受的兼容成本是维护当前版本索引、请求 deadline/取消、迟到确认校验以及完整替换时的整体重置。这些工作保证未变化资源可保留，旧请求不会占住队列。剩余小规模端到端差值没有逐项归因，明确作为本机观测成本保留。采用按源复用的依据是局部替换注册 8→1、首个 SVG 和稳定耗时显著下降，同时完整替换的归一化与首个 SVG 对照保持；不承诺完整替换总体提速。

为隔离顺序矩阵中“先局部更新、再全量替换”的分配历史影响，使用相同冻结生产 bundle，挂载后先完整替换，再局部替换，每次更新前显式主线程 GC；每种规模各预热五次、记录五次。见 replacement-isolation.json（历史验证文件，已清理） 及 scripts/measure-replacement-isolation.mjs。这个对照改变了前置条件，不能替代上面的顺序矩阵，也不能证明 Worker/WASM 峰值或 GC 全部耗时。

首次 SVG 指 MutationObserver 观测到波形 path 的 d 属性首次变化；它是 DOM 几何更新时刻，不是屏幕合成/像素首次呈现，也可能是最终采样前的占位几何。单位 ms，中位数 / p95。
