## Context

当前分析项目采用原生 TypeScript/D3 SVG 引擎及 Vue 适配层，根入口、/native、/vue 已分离；展示项目导出原生 Waveform 类，Vue 包装目前位于其 Demo。两个项目各有动画、数据、配置、渲染和测试实现。本文的“双组件”指两个独立的原生能力；当前 /vue 仅公开分析组件，展示 Demo 的 Vue 容器包装不等于新增公共 Vue 组件。

以实施开始时两边实际源码和测试为基线，记录 Git 修订及相关未提交变更。既有 add-animation-system 文档包含历史 Vue 渲染结构，不能直接当作当前架构；本变更保持既有行为，不覆盖其他变更的任务或证据。

## Goals / Non-Goals

**Goals:** 一个发布包、两个独立组件、实际共用的内部基础模块、一套动画系统，以及统一组件示例站点。保留现有分析入口和两边既有行为（展示组件仅调整导入来源）。

**Non-Goals:** 不统一两边全部数据格式、业务调度和渲染器；不强制新增展示 Vue 公共组件、PNG 导出或分析专有交互；不引入 ECharts 式 use() 注册机制或全局 Vue 安装插件；不新增独立发布子包；不自动发布、删除原仓库或停用原包。

## Decisions

### 1. 单包与内部共享边界

展示模块迁入 src/display/，新增 src/display.ts 和 src/analysis.ts 公共入口；根入口聚合分析导出与展示 Waveform。共享模块按职责放入内部目录（如 src/shared/）；内部提取不自动扩大公共 API。

| 包入口 | 职责与导出契约 |
| --- | --- |
| waveform-analysis | 保留现有全部公开符号；新增 Waveform 及明确命名的展示类型；保持框架无关 |
| waveform-analysis/analysis | 分析专用入口，提供当前分析根入口的公开符号，不依赖展示业务模块 |
| waveform-analysis/display | 导出 Waveform、defaultOptions 及原展示包公开类型，保留其局部命名；不依赖分析业务模块 |
| waveform-analysis/native | 保留现有根入口兼容别名和实例注册表身份，不将其描述为分析专用精简入口 |
| waveform-analysis/vue | 保持现有 WaveformChart 及类型；内部连接分析入口/实现，避免通过聚合根入口带入展示 |
| waveform-analysis/style.css、waveform-analysis/native/style.css | 保留旧路径和分析样式兼容性；样式策略见下文 |

现有 src/native.ts 为 export * from './index'。将其强行改成分析专用入口，会与已有“根入口兼容别名”的约定冲突。因此新增 /analysis 承担明确的依赖隔离；/native 继续跟随根入口。分析导出清单移至独立入口后由根入口显式重新导出，避免循环依赖。原根导入保持可用，文档用 root 的命名导入介绍便利使用，用 /analysis、/display 介绍严格按需消费。

根入口展示类型统一使用 WaveformDisplay 前缀，例如 WaveformDisplayData、WaveformDisplayOptions、WaveformDisplayPoint；展示 defaultOptions 在根入口命名为 waveformDisplayDefaultOptions。/display 保持 WaveformData、WaveformOptions、WaveformPoint、defaultOptions 等原有局部名称。迁移前枚举原展示 src/index.ts 的所有公开类型，包括事件、动作和动画，形成逐项名称映射及类型消费测试；保留原分析符号含义。无需新增默认导出、组件自动注册或公共 /shared 入口。

目标公开入口示例（是否完成以独立包消费证据为准）：

```ts
import { init, Waveform } from 'waveform-analysis'
// 严格按需的等价用法
import { init as initAnalysis } from 'waveform-analysis/analysis'
import { Waveform as Display } from 'waveform-analysis/display'
import type { WaveformDisplayOptions } from 'waveform-analysis'
import type { WaveformOptions } from 'waveform-analysis/display'
// Vue 适配入口单独消费
import { WaveformChart } from 'waveform-analysis/vue'
```

依赖方向为分析/展示模块指向共享层。共享层不得依赖组件业务类型、Vue 或 Demo。/analysis 与 /display 的源依赖图和按需构建产物不得包含对方业务代码；共用算法和动画代码允许共享构建块。ESM 根入口只使用一个组件的生产构建也必须验证未使用组件业务代码被消除；不以 exports 字段或 sideEffects 声明替代实际验证。

类型解析覆盖项目支持的 TypeScript moduleResolution（至少 bundler、NodeNext 和现有传统解析消费用例），同步 exports、typesVersions、tsconfig.lib.json 的入口 include 和声明后处理；新增入口不能只加入 Vite 配置而遗漏 .d.ts。展示源码的相对 .js 导入需要在 TypeScript 声明与边界检查工具中正确解析到源码，不得通过跳过未解析依赖获得假通过。未安装 Vue 时根、/native、/analysis、/display 的运行时及声明消费须成功；/vue 才需要 Vue。每种格式内部同一种组件跨入口共享同一构造器及注册表，并共用动画实现；两种组件之间不合并注册表。不额外承诺 ESM 与 CJS 混用时共享进程内单例。同页兼容范围为当前包的一份安装中多个组件实例，使用各自宿主容器；本变更不新增“两种组件占用同一个宿主容器”或多版本包副本协同管理的承诺。

公开导出映射须同时审查运行时和声明依赖。保留旧公开类型与方法签名，但共享层实现类不因生成 .d.ts 而获得受支持的深路径导入承诺；文档示例仅使用 exports 声明的路径。类型映射须检查与已有 WaveformDisplayMode 等分析符号冲突，不能仅机械添加前缀。

样式继续显式加载，保留 CSS 的 sideEffects 声明。展示组件现有 SVG 属性样式应在未加载分析 CSS 时正常工作；若迁入过程中确需独立 CSS，新增并验证 /display/style.css，禁止要求展示用户加载完整分析 CSS。旧样式路径不得消失；同页加载不修改宿主通用标签样式。根/子入口在无 DOM 环境中仅导入模块不得启动时钟、注册全局监听或创建图表；这不代表承诺服务端图表渲染。

### 2. 共享能力按行为归类

实施前建立清单，记录两边路径、调用者、行为差异、选定共享接口和回归测试。优先抽离科学计数法指数、舍入和指数文本：两边阈值均为 0.001/1000，采用五位有效数字；轴标题/顶端刻度的单位拼装保留适配。

曲线映射、点符号、线型、裁剪和 SVG 基础操作可共享。现有点划线分别为分析的 8 5 1.5 5 与展示的 8 4 2 4；点面积分别为 π(size/2)² 与 4size²。通过参数适配保留外观，不将统一默认值伪装成重构。

尺寸观察、容器解析和资源释放可提取通用工具，但尺寸策略与实例注册表按组件隔离。配置快照和比较仅在循环引用、函数身份、非普通对象、TypedArray 和数据所有权语义明确后复用。

数据模型、配置合并、可见性、事件和业务调度暂保留组件策略。分析按顶层合并配置，展示对多个嵌套字段合并；分析事件对相同回调去重，展示分别注册；分析按帧分阶段调度并等待采样，展示同步处理更新。不得通过通用替换改变这些行为。

### 3. 一套动画系统与两个适配层

以分析项目 src/animation/core/ 为候选公共运行时，先用两边兼容矩阵验证，再补齐展示需要的能力。统一时钟、帧驱动、任务/句柄、播放暂停恢复、取消结束、缓动、插值、冲突处理和资源清理。共享入场裁剪、更新过渡及淡入淡出策略；匹配规则和阈值可由组件策略提供。

“一套运行时”指唯一的引擎实现，不要求所有图表共用一个 Animator 对象或整个页面只有一个 RAF。公共引擎可按实例或 document 创建调度器，禁止的是组件适配层重复实现时钟与任务状态机。每个实例有独立 owner/作用域。owner 至少区分实例、动画类别和内部对象身份；输入的 series.id/point.id 不可直接作为共享任务键。重复或缺失 ID 沿用组件原匹配/降级规则，不能为了通用匹配而改变系列身份或顺序。共享引擎代码不意味着共享可变状态；如果复用同一帧源，也必须保证任务隔离，不能跨文档错误复用 window。分析/展示适配层负责准备动画输入、提交临时画面、提交终态和清理；不能再维护第二套时间循环或任务状态机；允许适配层保留布局快照、匹配结果和提交版本等业务状态，不将这些状态误判为重复引擎。分析的标注和分页动画作为同一运行时上的扩展。

已公开的 globalAnimator 及 pauseAll/resumeAll 等行为继续兼容，但组件销毁、暂停和取消只能操作自身 owner 的任务，禁止调用共享调度器的全局清理方法影响消费者任务。不得为了接入展示而扩大已有全局方法的影响范围；按兼容矩阵保留旧公开控制行为。需要隔离时使用同一引擎创建独立实例，而不是复制引擎实现。

分析根入口已公开的 Animation、Animator 等符号，以及两组件公开的动画控制接口及配置通过兼容包装保留；展示内部未公开的类不因此升级为公共 API。对公共动画能力不做无意删减；统一运行时与业务更新调度分离，保留 rendered/finished 和导出稳定性语义。

动画只操作 presentation，不修改原始数据、业务坐标域或事件值。秒坐标不变量适用于分析组件；展示保留调用者的原始 X 坐标和轴单位含义，不额外引入秒/毫秒转换。分析的 TypedArray、采样几何、缓存和现有低分配路径必须可直接接入；不能要求逐帧展开全量点对象。采样结果、配置更新和动画替换通过版本/作用域避免旧帧覆盖新状态。

两组件的兼容测试分为公共运行时契约与组件策略契约，不强求不同的旧行为相同：

| 场景 | 必须保留的边界 |
| --- | --- |
| 展示导出 | toSVGString() 同步提交动画终态并返回字符串，当前 finish(true) 的完成通知延后至微任务；销毁后返回空字符串。downloadSVG 沿用该路径 |
| 分析导出 | exportImage() 保留异步稳定性屏障，以及 stale/cancelled/timeout 等错误语义；不能为复用展示逻辑而自动 finish 所有动画 |
| 展示通知 | animation 与 animationUpdate 是两个类别，分别维护 onComplete/onAbort；一个批次可合法通知两个类别，不能合并为一次总通知 |
| 公共任务终止 | 每个任务完成/中止互斥且只通知一次；展示类别通知是适配层的聚合契约，不与任务个数绑定 |
| 环境偏好 | 隐藏文档、手动暂停及 prefers-reduced-motion 按兼容矩阵验证；恢复一个原因不能覆盖另一个暂停原因，减少动态效果时沿用组件终态及通知策略 |
| 错误与销毁 | 保留组件原有同步抛错/异步报告、清理和通知次序；用户回调异常不能阻塞另一实例 |

不得把这些差异转换成新的公共配置开关来逃避兼容；适配层应承担策略转换。每个类别的回调计数、顺序及重入用例必须写出明确期望。

### 4. Demo 和工程统一

Demo 按分析/展示分组，提供示例说明、运行视图、代码和同页共存页。保留原有控制面板及场景；共享外壳、基础控件、错误提示和数据生成器，数据格式通过适配转换。统一 Ant Design Vue 主版本并验证控件行为；选定版本和迁移影响写入兼容清单，不同时引入第二套 UI 框架或无关主题重构；Demo 依赖不进入库运行时。

统一 Node 22、pnpm 10.32.1、构建、测试和发布；展示测试迁入对应所有权目录，保留发现范围和覆盖率。Demo 消费构建包入口，不引用同级项目或库内部源文件。组件页面采用路由懒加载；统一站点不要求首屏同时加载两种组件。路由离开时释放图表、监听及动画任务，反复切换不得出现残留 SVG 或活动任务累积。

分析 ChartInstance 当前没有直接 pause/resume 动画方法；Demo 不显示无法由公开 API 实现的对称按钮。展示使用其 animation 控制接口，分析展示现有动画开关/更新操作；公共内核暂停隔离由契约测试验证。公开的独立 Animator 示例可以单列，但不能伪装成对分析图表实例的控制。

## Migration Plan

先记录双项目基线和兼容矩阵，再迁入展示模块并通过独立消费测试；随后抽离低风险共享能力，定义并验证统一动画接口，分别迁移两个适配层；最后移除重复动画内核，完成统一 Demo 和全部门禁。各步骤保持可回退，不能以删除兼容测试消除差异。

阶段门禁：第 1 阶段先产出兼容与性能基线；第 2 阶段必须完成双组件独立包消费验证后才进行共享重构。第 4 阶段公共内核测试通过后，第 5 阶段分别迁移适配层；两边契约均通过后才能删除旧内核。Demo 外壳可提前准备，最终同页验收依赖两个适配层完成。

迁入展示模块后应立即处理 src/ 的 450 行限制、严格类型和 ESLint 约束，不留到最终门禁才拆分大文件。拆分按职责进行，不能通过排除目录或降低门禁解决。

## Risks / Trade-offs

- 动画整合可能改变暂停、重入、取消和完成回调时序：使用可控时钟的公共契约测试，并对两个适配层参数化运行。
- 同名配置和视觉参数含义不同：固定现状，通过适配保留，另行提出主动行为变更。
- 大数据性能退化：先记录同硬件/浏览器/数据的基线及数值预算，整合后比较帧时间、分配/堆占用和任务释放；预算不能在失败后放宽。
- 共享模块过重：验证按需入口依赖图，防止展示入口带入分析采样、标注或 Vue。

## Validation Strategy

共享纯函数测试、双组件兼容回归、统一动画运行时与适配层测试、独立 ESM/CJS/类型/CSS 消费测试，以及组件消费页和 Demo 的桌面/小容器浏览器验证共同验收。记录实际命令、结果、性能基线和截图，未执行不标记完成。

包消费测试使用实际 .tgz，至少分两个独立临时项目：原生项目不安装 Vue（也不自动补装可选 peer），Vue 项目安装声明支持的 Vue。不能复用一个装有 Vue 的父目录/node_modules；原生测试须记录 Vue 解析失败作为环境前提，再验证原生 JS 和类型入口成功。现有 scripts/test-package.mjs 默认安装 Vue，需要扩展而不是仅增加导入语句。声明消费使用 skipLibCheck: false，不通过工作区 alias 或路径重写掩盖缺失依赖。

Tree shaking 验证固定生产打包器、版本和设置，保存模块组成/构建元信息及产物体积；不能只搜索压缩后的类名，也不能将共享数学/动画模块误判为另一组件的业务依赖。CJS 子入口的隔离通过可达模块依赖图检查，不要求无打包器的根 require 自动消除未使用组件。

### Evidence and Completion

实施证据放在本变更 evidence/ 下，至少包含：baseline.md（两边修订、数据/尺寸/浏览器、公开 API 和路由清单）、compatibility-matrix.md（行为、策略、期望、测试路径）、reuse-inventory.md（复用或保留理由）、performance-budget.json（预先填写的数值预算和测量条件）、verification.md（规格→任务→测试/截图/命令结果映射）。以上是实施交付物，不在规划阶段伪造测量结果。

性能记录须区分冷启动与预热、固定数据规模和更新序列，记录预热次数、重复测量次数、帧时间统计口径（含 P95）、堆/分配测量方法及允许噪声；报告单组件和双组件并行情形。缺少可用环境或指标时标记未验证，不能据此勾选性能任务。若基线已有失败，记录复现与归属，最终交付说明仍未解决的阻塞，不能宣称全门禁通过。

性能基线与整合版本须使用相同的生产消费构建、依赖版本和测量脚本；原始 dist 文件大小仅作清单，不能直接与消费构建体积比较。按入口统计实际可达 JS，CSS、Worker 和 WASM 单独列出，不遗漏异步资源；映射旧分析根入口到新 /analysis、旧展示入口到新 /display，聚合根入口另列双组件预算。缺失基线或对应关系时，该项保持未验证，不改变既定预算。

性能脚本必须确认动画实际启用并发生帧提交，分别测量初始化、入场和更新阶段；不能将包含动画结束后空闲帧的全局 RAF 间隔直接标为动画 P95，也不能将构造函数耗时标为首屏完成耗时。固定有效采样窗口及最少样本数，并记录浏览器错误、Worker 加载和采样后端；意外加载失败或降级使本轮比较无效，必须修复后重测，保留失败记录。仅记录更新前后的 performance.memory 数值不能证明无持续堆增长：另以固定多轮创建/更新/销毁、统一 GC/等待策略记录销毁后保留堆趋势，同时检查宿主仍挂载时的 SVG 清理及 RAF、observer、监听资源；先删除宿主再数 SVG 不能证明组件自行清理。

每份最终证据记录命令、退出码、时间、工具版本及受测源码/构建产物指纹；未提交工作区不能仅记录 HEAD。类型、构建、包消费及浏览器证据应对应同一最终源码和产物；测试期间修改相关源码或重建 dist 后，受影响证据需重跑。中间失败与成功都保留，verification.md 区分“已运行通过”“失败”“待运行”和“源码变化后待复验”，不得凭任务描述或脚本存在勾选完成。

兼容矩阵逐场景填写准确测试路径、用例名、同步/微任务边界、回调顺序及次数，包括回调重入后的有效版本；“以源码为准”只用于定位基线，不能替代明确的验收预期。跨 document 验收使用独立 iframe 宿主，验证时钟、尺寸监听和销毁均属于宿主 window；主页面同页测试不能替代该场景。

任务只有在实现、对应测试和证据齐全后才可勾选。OpenSpec 校验只证明规划结构有效，不表示实现通过兼容或性能验收。
