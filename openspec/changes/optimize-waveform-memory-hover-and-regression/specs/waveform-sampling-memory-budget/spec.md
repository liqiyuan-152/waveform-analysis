## ADDED Requirements

### Requirement: 分配前索引预算检查

采样索引 SHALL 在创建某层 TypedArray 之前检查所需字节与剩余额度；不能容纳该层时 SHALL 不分配该层数组，并保持正确的后备采样行为。分配失败 SHALL 不虚增已用额度。

#### Scenario: 零预算的重复采样

- **WHEN** 索引预算为零或不足以容纳下一层，并对不同可视范围重复请求 extrema 或 sum 采样
- **THEN** 不创建被预算拒绝的层数组，返回与既有后备算法一致的结果

#### Scenario: 分配失败或数据失效

- **WHEN** 数组分配抛出异常，或数据集被替换、销毁
- **THEN** 额度统计与有效保留资源一致，旧索引不被后续 revision 使用

### Requirement: 内存候选由端到端证据决定

传输与总预算候选 SHALL 比较完整更新及恢复成本，明确源、快照、Worker、索引、缓存和 WASM 的所有权与测量范围。采用方案 SHALL 不 detach 消费者输入或故障恢复需要的缓冲区；没有足够收益证据时 SHALL 保留现状并记录理由。

#### Scenario: 传输后 Worker 故障

- **WHEN** 候选传输完成后 Worker 失败，消费者仍持有输入
- **THEN** 输入保持可读，当前 revision 能按既有回退策略恢复，旧响应不能覆盖新状态

#### Scenario: 候选收益不足

- **WHEN** 端到端差异未超出测量噪声或出现无法解释的恢复退化
- **THEN** 不接入该候选，保存比较范围、结果及不采用决定
