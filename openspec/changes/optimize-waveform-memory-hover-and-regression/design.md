## Goals / Non-Goals

目标：降低确定性的无效分配和 DOM 重建；改善 WASM 不可用时紧凑输入的性能；把核心浏览器行为纳入持续验证；用证据决定复杂的内存和流水线优化。

非目标：引入 Canvas/WebGL、流式追加 API、共享 Worker、SharedArrayBuffer、新公共内存配置、改变采样算法或重写 Git 历史；本阶段也不承诺固定百分比提速。

## Decisions

### 1. 预算检查先于 TypedArray 分配

按层长度和元素宽度计算字节数，在构造数组前检查可用额度。实际分配成功后提交计数；异常不得留下虚假的已用额度。预算不足时沿用已有正确降级，不反复尝试同一不可能容纳的层。

同时检查 extrema 和 sum 两条路径。测试观察构造分配和结果正确性，不能只检查 `byteLength` 统计。当前预算限制的是索引保留量，不将其包装为整个进程内存上限。

### 2. Tooltip 持久行与尺寸失效

使用稳定系列 ID 管理行节点，仅在系列增删或重排时更新结构；数据、单位、标签和颜色分别更新。内容只用 textContent 写入。相同内容仅位置变化时复用已知尺寸，内容变化、容器变化和 ResizeObserver 通知使尺寸失效。

定位继续使用现有 tooltipPlacement：内容能放入容器时遵循当前翻转和边距；内容高于可用高度时保持 top=8px 的现有顶端钳制及原有溢出/裁切行为，不承诺所有行均在容器内可见。本次不新增限高、滚动、截断或行数限制。覆盖多系列超高内容、长标签以及容器缩小时的文本完整性与既有定位结果。

保持 Tooltip 隐藏、销毁、跨 ownerDocument 和多实例隔离；允许首次显示或内容宽度改变时进行必要测量。完整源最近点、缺失值、时间单位和 point-hover 事件保持现状。按可见文本、定位和生命周期验收，节点计数只用于性能证据。

### 3. 紧凑输入的 JavaScript 索引

优先抽象数值访问接口，让索引复用现有 x/y 或等间隔时间元数据，不为适配索引创建全量点对象。首轮仅为 peak/min/max/minmax 懒建索引，源索引、相等值取舍与边界补点须与当前参考结果完全一致。none 保留直通；LTTB、预算不足及不支持策略继续使用原后备路径。

sum/average 默认保留 sampleWaveformReferenceValues 的顺序聚合，不直接接入分层 sum 索引。审核探针显示，y=[1e16, 1, -1e16, 1]、单桶时，现有索引的 sum/average 为 0/0，数值参考实现为 1/0.25。不得通过放宽容差掩盖差异。既有对象点 sum 索引的预算修正不扩大为聚合算法重写。

聚合索引仅作为后续条件候选：先覆盖大动态范围、正负抵消、有限输入的中间溢出、非有限结果和不同桶边界。保留普通数值测试的原容差，对抵消示例及 NaN/Infinity 分类单独断言；无法证明兼容则继续顺序聚合，不阻塞极值索引交付。

回归 typed、samples、非有限值、乱序、重复 X、稀疏 sourceIndexes、范围边界、替换和销毁。采样结果与既有参考实现按原容差比较，不能通过改变算法或查询完整数据语义获得提速。

### 4. 总内存和传输作为有条件候选

分别计量消费者输入、主线程私有源、恢复快照、传输副本、Worker 仓库、索引、输出缓存和 WASM 内存。比较单实例多系列与多实例场景，说明可测与不可测范围，不能以 JS heap 代替全进程峰值。

先复核先前 transfer 数据，再测完整替换到稳定帧和故障恢复。只有端到端延迟或峰值内存改善超出测量噪声、且没有无法解释的回退退化时才采用。不得 detach 消费者数组、恢复快照或仍被缓存使用的输出。

总预算方案先限定为内部实例级可回收索引/缓存，不淘汰业务源数据；若需要公开配置或跨实例协调，另行提出 API 方案。未采用候选也须留下原因和测量限制。

### 5. 浏览器验证分层

最低矩阵如下。“核心场景”统一指悬停、缩放、受控图例、销毁及 SVG/PNG 导出，均覆盖原生/Vue 与 1280px 桌面、360px 小容器。复用现有脚本及启动/清理逻辑。

| 工作流                                             | 必跑浏览器                | 必跑内容                                                                                | 失败处理                                       |
| -------------------------------------------------- | ------------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------- |
| .github/workflows/ci.yml 的 push/PR                | Chromium                  | 核心场景及现有独立包消费                                                                | 阻断验证                                       |
| 新增 GitHub 每周定期工作流，支持 workflow_dispatch | Chromium、Firefox、WebKit | 各浏览器全部核心场景、交互耗时、重复创建/替换/销毁资源检查；Chromium 另采集专用内存指标 | 对应 job 失败并保存诊断                        |
| .github/workflows/release.yml                      | Chromium                  | 核心场景及实际 tarball 消费                                                             | 阻断 npm 发布和 Release 创建                   |
| .gitea/workflows/package.yml                       | Chromium                  | 核心场景及实际 tarball 消费                                                             | 阻断双 registry 发布、Release 创建和 Demo 部署 |

发布不得以最近一次定期结果代替当前提交验证；通过隔离副本或发布步骤桩测试阻断，不触发真实发布。Gitea 无须重复部署定期跨浏览器任务。浏览器安装/启动失败、必跑场景异常或超时均返回非零，不得以 skip、continue-on-error 或删除场景使矩阵通过。

Firefox/WebKit 不支持的 Chromium 专属堆采样可记录 N/A，附能力检测及原因；功能、耗时和可移植资源计数仍必跑。Chromium 专用内存任务必须至少采集预先选定的一项受支持指标，说明覆盖范围；采集失败或全部指标缺失使任务失败。JS 堆不等于全进程峰值，WebKit 自动化不等于真实 Safari/iOS，辅助技术单独注明。

性能数据固定输入种子、构建配置、浏览器版本和硬件信息；预热至少 5 次，测量至少 20 次，保存中位数和 p95。先采集至少 3 轮基线再锁定每项阈值、绝对容差与重测规则；无阈值的报告不得声称性能门禁生效。功能失败始终返回非零。

### 6. CI 产物复用与工具链

先记录 coverage → build → test:package → pack/prepack 调用次数和耗时。coverage 产物与发布产物分离；候选只在同一验证链明确构建发布产物后复用，不以 dist 存在为依据跳过准备。

复用凭据须关联源码、配置、锁文件、工具版本与产物校验值，拒绝过期、缺失或篡改产物。保留独立 test:package、build、typecheck 和直接 pack 的完整行为。复杂度超过收益时维持现状并记录决定。

提供与 CI 协调的 Node 22 版本入口及 pnpm 10.32.1 说明。新增临时诊断写入系统临时目录，长期证据保存命令、版本、摘要和最小数据；不批量删除或全局忽略已有 evidence。

## Risks / Trade-offs

- 节点复用可能留下过期标签或错误顺序，必须覆盖元数据更新、系列重排和缺失值。
- 索引会以额外保留内存换取查询速度，必须同时报告冷启动、稳定交互和释放结果。
- transfer 可能只是移动复制成本，并破坏恢复能力，必须先测量再决定。
- 跨浏览器和性能任务增加 CI 成本，采用 PR/定期分层，不降低既有功能门禁。
- 构建复用可能放行旧包；没有可靠产物身份时保留重复构建。

## Migration Plan

按索引预算 → Tooltip → 浏览器回归 → 紧凑降级 → 测量候选 → 工程配套分阶段实施。每阶段保持独立可评审的改动并验收；本轮授权不提交、推送或发布；回退只撤销该阶段优化，保留回归用例及兼容要求。已有缓存和发布流程保持为可靠回退路径。
